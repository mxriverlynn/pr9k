# Phase 1 — Implementation Discovery Notes

Single source of truth for project context across the planning team. Specialists must read this first and not re-grep what is already here. They may search further for what their domain specifically needs that this file does not cover.

## Tech Stack

- **Language:** Go 1.26.2 — single Go module at `src/`, module path `github.com/mxriverlynn/pr9k/src`.
- **CLI framework:** [spf13/cobra](https://github.com/spf13/cobra) v1.10.2 + spf13/pflag v1.0.9. POSIX-style flags, subcommand support, `--version` built-in.
- **TUI framework:** [Bubble Tea](https://github.com/charmbracelet/bubbletea) v1.3.10 + [Lip Gloss](https://github.com/charmbracelet/lipgloss) v1.1.0 + [bubbles/viewport](https://github.com/charmbracelet/bubbles) v1.0.0.
- **Other deps:** `atotto/clipboard`, `charmbracelet/x/ansi`, `mattn/go-runewidth`, `muesli/termenv`, `rivo/uniseg`, `golang.org/x/sys`, `golang.org/x/term`.
- **Sandbox:** Docker is an unconditional runtime requirement for any workflow with claude steps (ADR `20260413160000-require-docker-sandbox`). Image is `docker/sandbox-templates:claude-code`.
- **No PTY plumbing.** Subprocess I/O exclusively via `os.Pipe()` (stdout/stderr fds). No `creack/pty`, `forkpty`, `ConPTY`. No PTY allocation anywhere in the repo.
- **Current version:** `0.10.0`, single source of truth at `src/internal/version/version.go`.
- **Build:** `make build` → `./bin/pr9k`. `cd src && go build -o ../bin/pr9k ./cmd/pr9k`. `go run` does not work because `os.Executable()` resolves to a temp dir.
- **Test/CI:** `make test` (= `cd src && go test -race ./...`); `make ci` (test + lint + format + vet + vulncheck + mod-tidy + build). golangci-lint v2.11.4 pinned.

## Coding Standards (full list, paths + one-liners that bear on Phase 1)

All standards live under `docs/coding-standards/`.

- [`error-handling.md`](../../../coding-standards/error-handling.md) — Package-prefixed error messages (`fmt.Errorf("preflight: ...: %w", err)`). Include file paths in I/O errors. Use `errors.Is`/`errors.As` for wrapped errors. Validators must distinguish fatal/non-fatal severity (mirror of `validator.FatalErrorCount`). **Phase 1 implication:** every cmux-preflight error message follows the package-prefixed pattern; the cmux preflight participates in the existing severity model.
- [`concurrency.md`](../../../coding-standards/concurrency.md) — Snapshot-then-unlock under mutex. WaitGroup drain before `cmd.Wait()`. Concurrent stdout+stderr drain. Document setter ordering on goroutine-owning types. Mutex-protect shared `io.Writer`. Channel-based action dispatch. Non-blocking sends from signal handlers. Wrap blocking ops in `tea.Cmd` closures. Signal-path and completion-path must converge cleanly (existing pattern at `main.go:281-330`). **Phase 1 implication:** cmux-call timeout, dismissal-observation goroutine, and signal handling all sit on top of these patterns.
- [`api-design.md`](../../../coding-standards/api-design.md) — Bounds guards on indexers. Precondition validation at function boundary. Compile-time interface-satisfaction assertions at the type's declaration site. Panicking sentinels for required callbacks. Don't ship hidden/stub commands. Visible feedback on rejected mutations. Exhaustive switches with `panic` fallback (no silent `default`). **Phase 1 implication:** the cmux-RPC client interface plus its real implementation goes in the cmux client package; tests use a fake; compile-time assertion at the real type's declaration site.
- [`go-patterns.md`](../../../coding-standards/go-patterns.md) — Resolve `os.Executable`/`os.Getwd` with `filepath.EvalSymlinks` (already in `args.go`). Extract OS-dependent calls into `...With` testable inner functions (canonical example: `resolveWorkflowDirWith`). 256KB scanner buffer for subprocess output. Sanitize external program output before reflecting to terminal. `exec.CommandContext` with timeout for external probes. `time.NewTimer` + `defer Stop()` for per-op deadlines (NOT `time.After`). Trim env-var values. Modern octal `0o600`/`0o700`. Typed string constants for serializable enums. **Phase 1 implication:** the cmux-RPC client uses `time.NewTimer` for the per-call timeout (parent D27); the dismissal observer also.
- [`testing.md`](../../../coding-standards/testing.md) — `-race` is non-negotiable. Test closeable types for idempotency (`Close` twice). Test bounds guards explicitly. Test all file I/O error paths. `runtime.Caller(0)` for test-helper path resolution. Test doubles need mutexes too. Inject signals for blocking receives. **Phase 1 implication:** the cmux-client fake is a real test double with sync; the dismissal observer's blocking receive needs an inject point in tests.
- [`file-writes.md`](../../../coding-standards/file-writes.md) — `atomicwrite.Write` for durable replacement. `O_CREATE|O_EXCL|O_WRONLY, 0o600` for initial temp files. `O_TRUNC` prohibited in new code. Phase 1 has no Phase-1-introduced file writes (preflight already creates `.pr9k/`).
- [`lint-and-tooling.md`](../../../coding-standards/lint-and-tooling.md) — No lint suppressions in any form. No "pre-existing error" exception. Every finding must be fixed. **Phase 1 implication:** no `//nolint`, no `.golangci.yml` exclusions, no `--no-verify`.
- [`versioning.md`](../../../coding-standards/versioning.md) — `version.Version` is the single source of truth. The CLI surface (flags, exit codes, `--version` output) is part of pr9k's public API. **Phase 1 implication:** adding the `--cmux` flag is a public-API addition. While in `0.y.z`, additions bump MINOR; under post-1.0 semver, additions bump MINOR. Bump is its own commit (or combined with docs-only). Phase 1 ships → MINOR bump.
- [`documentation.md`](../../../coding-standards/documentation.md) — Feature docs ship with the feature, not as follow-ups. Update CLAUDE.md when adding new doc files. Doc code blocks must stay consistent with production code. Document external tool deps. **Phase 1 implication:** cmux setup how-to and any new feature/code-package docs land in the same PR; CLAUDE.md gets the new entries.
- [`tui-rendering.md`](../../../coding-standards/tui-rendering.md) — Plain-text-first ANSI composition. `lipgloss.Width()` for visual width. Generation counter for stale async banners. Render file decomposition. **Phase 1 implication:** Phase 1 produces no TUI; this standard governs Phase 2.

## Code Touch Points

### Entry point — `src/cmd/pr9k/main.go`
- `main()` (line 128): orchestrates parse → startup → wire actions/keyHandler/statusRunner/header/Bubble Tea program → spawn workflow goroutine → register signals → block on `runWithShutdown` → exit.
- `startup()` (line 62): runs `steps.LoadSteps` → `validator.Validate` → `preflight.Run`. Collects all errors before printing. Prints fatal validator findings + preflight errors → exits non-zero. Otherwise prints non-fatal findings + warnings, builds `services{log, runner, stepFile}`, returns.
- `hasClaudeSteps(sf)`: scans Initialize/Iteration/Finalize for any `IsClaude` step. Used by both `startup` (to gate preflight) and `buildRunConfig`.
- Signal handling at lines 281-330: `signal.Notify(sigChan, SIGINT, SIGTERM)` → handler goroutine `<-sigChan` → `keyHandler.ForceQuit()` → wait on `workflowDone` or 2s → `program.Kill()`. After `program.Run()` returns: `signal.Stop(sigChan)` → wait on `workflowDone` or 4s → exit `1` if signaled else `0`.
- The `--cmux` flag does not exist today.
- Subcommands wired via `cli.Execute(newSandboxCmd(), newWorkflowCmd())` (line 130).

### CLI parsing — `src/internal/cli/args.go`
- `Config{Iterations, WorkflowDir, ProjectDir}` is the public CLI shape.
- `newCommandImpl(cfg, ranE)` registers flags via `cmd.Flags().IntVarP(...)` / `cmd.Flags().StringVar(...)`.
- `RunE` resolves project-dir then workflow-dir; both go through `filepath.EvalSymlinks` and `os.Stat` for "is directory".
- Phase 1 needs to add a `Cmux bool` field on Config, register `--cmux` (cobra `BoolVar`), and propagate it down. The two-pattern `newCommandImpl(cfg, ranE *bool)` is the canonical extension shape.
- `flagSplitGuidance` is the post-parse error transformer for legacy-flag confusion. Phase 1's new flag does not need a similar shim unless it conflicts with existing names.

### Preflight — `src/internal/preflight/run.go` and `docker.go`
- `Run(projectDir, profileDir, hasClaudeSteps, p Prober) Result` runs the standard preflight. **Already creates `<projectDir>/.pr9k/` on first run** before checking anything else.
- When `hasClaudeSteps` is false, `Run` returns immediately after the `.pr9k` mkdir. Profile-dir and Docker checks are gated.
- `Prober` interface (3 methods): `DockerBinaryAvailable() bool`, `DockerDaemonReachable() error`, `SandboxImagePresent() (bool, error)`. `RealProber{}` is the production impl. All probes use `exec.CommandContext` with a 10s timeout (already follows the `go-patterns.md` external-probe rule).
- `CheckDocker(p)` returns `[]error` collecting findings; `CheckProfileDir(profileDir)` returns single error.
- **Phase 1 implication (D8):** the cmux preflight is sequenced *after* the standard preflight. Two viable shapes: (a) extend `preflight.Run` with a new `cmuxRequired bool` parameter and a separate cmux-prober interface, (b) keep `preflight.Run` unchanged and add a separate `cmux.Preflight(...)` call in `startup()` that runs only when `cfg.Cmux` is true. The second shape preserves the existing API and isolates cmux concerns.
- Severity model: standard preflight surfaces errors only (no Severity tier), but the validator (called in parallel from `startup`) does. The shared "zero fatal errors = success" rule is enforced in `main.go:74`.

### Workflow runner — `src/internal/workflow/`
- `workflow.NewRunner(log, projectDir)` returns the subprocess runner used by every step. It sets `cmd.Dir = projectDir` so `gh`, `git`, `claude` operate against the target repo.
- `workflow.Run(runner, proxy, keyHandler, runCfg)` is the existing run loop. Phase 1 does NOT exercise this path because the spec explicitly says no workflow runs.
- The placeholder processes Phase 1 spawns inside cmux panes are NOT invocations of `workflow.Runner`; they are simple subprocesses (or `pr9k` subcommands) that print a label and sleep.

### Sandbox — `src/internal/sandbox/`
- `BuildRunArgs` constructs the docker argv for claude steps. `BuiltinEnvAllowlist`, `cidfile`, `NewTerminator`. **Not used by Phase 1.**

### TUI — `src/internal/ui/`
- `model.go`, `header.go`, `log_panel.go`, `keys.go`, `orchestrate.go`, `selection.go`, `clipboard.go`, etc. — the existing Bubble Tea model.
- The `--cmux` mode bypasses this entire package (the cmux pane processes own their own rendering, in Phase 2). Phase 1 ships nothing inside `internal/ui`.
- Pre-population of `header.IterationLine` (lines 165-180 in main.go) shows the TUI is not started in `--cmux` mode at all — the Bubble Tea `program.Run()` call must be conditional on `!cfg.Cmux`.

### Logger — `src/internal/logger/`
- `NewLogger(projectDir)` creates `<projectDir>/.pr9k/logs/<run-stamp>.log` and exposes `RunStamp()`.
- **Phase 1 implication:** the spec says no `.pr9k/logs/` artifacts are produced in Phase 1 (no workflow runs). So `logger.NewLogger` must be skipped (or the log is created but not written to). Cleanest: skip logger creation entirely on the cmux Phase-1 path.

### ANSI sanitizer — `src/internal/ansi/`
- `StripAll(b []byte) []byte` strict ANSI escape sequence stripper. Already used by sandbox-create smoke test and workflowio recovery view.
- **Phase 1 implication:** `Coordinations`'s "launching terminal" row says cmux-supplied diagnostics are stripped of ANSI before printing. `internal/ansi.StripAll` is the existing tool; reuse, do not rewrite.

### Subcommands — `src/cmd/pr9k/`
- `sandbox.go`, `sandbox_create.go`, `sandbox_interactive.go`, `sandbox_shell.go` — the `pr9k sandbox ...` subcommand family. They share helpers (Docker check, image pull, profile dir handling).
- `workflow.go` — the `pr9k workflow` subcommand (workflow builder; `Hidden: true` per the api-design standard while incomplete).
- `wiring.go` — extracted helpers (`newModeGetter`, `newStatusLineSender`, `buildStatusLineConfig`, `buildRunConfig`, `runWithShutdown`).
- These illustrate the in-repo pattern for new subcommands and how they wire dependencies. Phase 1 does NOT add a subcommand (per parent D25 the launch surface is `--cmux` flag, not `pr9k cmux ...`).

### Versioning
- `src/internal/version/version.go` — `const Version = "0.10.0"`. Phase 1 ships → MINOR bump (e.g., `0.11.0`). Bump is its own commit (or combined with docs-only changes per the standard).

## Explicitly enumerated gaps (searched for and not found)

- **No existing cmux client code.** No `internal/cmuxctl`, no `cmux.sock` reader, no JSON-RPC 2.0 client. This is greenfield work. The investigation doc (`docs/plans/cmux-rebuild/investigation.md`) sketches an `internal/cmuxctl` package at ~200-400 lines.
- **No existing IPC layer between processes.** The current architecture has one TUI process; the orchestrator and the displays are the same Bubble Tea program. Phase 1 does not introduce IPC because no real workflow runs — the placeholder processes are isolated.
- **No PTY plumbing anywhere.** Subprocess I/O is `os.Pipe()` only. The cmux panes are real terminals (cmux is the renderer); the placeholder process just writes its label to its own stdout. No PTY work needed for Phase 1.
- **No existing per-call timeout pattern for socket clients.** `exec.CommandContext` is used for external-probe timeouts (Docker probes); the cmux RPC client will need its own per-call timeout shape. The closest existing pattern is `Runner.Terminate()` which uses `time.NewTimer` for SIGTERM→SIGKILL escalation.
- **No existing "two-mode launch" pattern in the codebase.** Existing mode-like behavior: `pr9k workflow` is a separate subcommand (workflow builder), not a flag-toggled mode of the run loop. Phase 1's `--cmux` is the first flag that toggles the run loop's presentation surface. The cleanest shape inherits the existing `startup()` → standard preflight → ... pattern, then branches on `cfg.Cmux`.
- **No existing test-fake convention for cmux-shaped clients.** The codebase uses interface-based fakes for `Prober`, `EditorRunner`, etc. Phase 1's cmux client follows the same convention; the shape is a `CmuxClient` interface in `internal/cmuxctl`, a `RealClient` impl, and a `FakeClient` in tests.
- **No existing "wait for external dismissal" pattern.** The launching pr9k process today waits on `workflowDone`. Phase 1 needs a new wait shape: "wait for cmux workspace removal OR placeholder process exit" (per Phase-1 D9). The closest in-repo pattern is the dual-wait in main.go's signal handler, but it's two channels, not the cmux-list/process-exit observation pair Phase 1 needs.
- **No CI plan for cmux integration.** Per Phase-1 OI-2, the team has not yet decided whether to use mocked cmux in CI, a live smoke test on a capable runner, or both. The build-outline OQ-2 recommends "mock the programmatic interface for Phases 1-5; revisit for Phase 6".
- **No pinned cmux version.** Per Phase-1 OI-1, the team has not yet picked a "tested against version X" floor for the setup how-to. The capability check in Phase 1 is method-presence-based and works regardless.
