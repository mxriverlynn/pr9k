# Feature Implementation Plan: Phase 6 — Robust Failure Handling

Phase 6 hardens the cmux multi-process architecture so every failure mode — a dying display pane, an operator pane-close, a stalled interaction channel, a hung or erroring cmux API call, and orchestrator process death — converges on a predictable, inspectable outcome. The implementation is predominantly **detection and convergence**: it adds a stall threshold and a content-independent liveness signal to `internal/interactionchannel`, a single one-way abort gate, and an abort-routing path into the synchronous `workflow.Run()` loop — and reuses the already-shipped `FireRunAborted`, `cmuxSidebar.ClearAll`, `WorkspaceDone` broadcast, `Runner.Terminate()`, and cmux error classifier. No new CLI flag, no new on-disk artifact, no version bump. Merge posture: a single PR; the liveness wiring is a go/no-go gate.

## Outcome

When this plan executes, the codebase contains:

- A new abort gate — a small `abortGate` struct (in `src/cmd/pr9k/`) wrapping a `sync.Once`, with the failure cause captured inside the `Do` closure and an exported `IsAborting() bool` accessor ([D-1](artifacts/implementation-decision-log.md#d-1-the-abort-gate-is-a-synconce-guarded-one-way-transition-with-the-failure-cause-captured-in-the-do-closure)). Every failure-detection path — the orchestrator's cmux-call path, the per-connection channel-stall path, the per-connection display-loss path, the mid-run cmux-error path — calls `gate.trigger(cause)`; the first caller wins and names the diagnostic, every later caller is absorbed.
- A separate `atomic.Bool runCompleted` flag set the instant `workflow.Run()` returns, checked by every detection path so a failure observed in the post-run window does not fire a spurious run-aborted notification ([D-2](artifacts/implementation-decision-log.md#d-2-a-runcompleted-atomicbool-closes-the-post-run-window-race)).
- A liveness emitter in `internal/interactionchannel` / `src/cmd/pr9k/`: a goroutine started in `runCmuxOrchestratorWith` after `AwaitReady` and before the workflow run, broadcasting a new zero-field `Liveness{}` message to every pane on a fixed `LivenessCadence = 10 * time.Second` ([D-3](artifacts/implementation-decision-log.md#d-3-the-liveness-emitter-is-a-10-second-cadence-goroutine-started-after-awaitready-the-per-connection-stall-timer-lives-in-readloop), [D-6](artifacts/implementation-decision-log.md#d-6-liveness-is-a-new-zero-field-message-type-with-wire-constant-liveness)).
- A per-connection 45-second stall timer (`StallThreshold = 45 * time.Second`, exported; threshold and an `onStall` callback injectable for tests) inside `readLoop` on both the orchestrator and display-pane sides, reset (Stop-drain-Reset) on every received message ([D-3](artifacts/implementation-decision-log.md#d-3-the-liveness-emitter-is-a-10-second-cadence-goroutine-started-after-awaitready-the-per-connection-stall-timer-lives-in-readloop)).
- A new `workflow.ExitReasonAborted` value distinct from `ExitReasonUserQuit`; an abort detected on a channel goroutine interrupts the synchronous `Run()` loop by calling `runner.Terminate()` then sending `ActionQuit`, and `runCmuxWorkflowAdapted` routes `ExitReasonAborted` to the abort sequence ([D-4](artifacts/implementation-decision-log.md#d-4-an-abort-detected-on-a-channel-goroutine-interrupts-the-synchronous-run-loop-via-terminate--actionquit-routed-by-a-new-exitreasonaborted)).
- An `Aborted bool` field on `WorkspaceDone` and a shared exported `RunAbortedToken = "run aborted"` constant; `runCmuxDisplayPaneWith` and `runCmuxFooterPaneWith` select on a `stalledCh` and on `WorkspaceDone`, render a final line containing the token, and return on either the orchestrator-death path or the clean-abort path ([D-5](artifacts/implementation-decision-log.md#d-5-panes-render-a-shared-run-aborted-token-aborted-bool-on-workspacedone-carries-the-clean-abort-path)).
- The mid-run cmux error classifier reusing the existing `cmuxctl/preflight.go` vocabulary (access-denied, auth, missing-method, unclassified-with-raw-code) routed into the abort diagnostic ([D-9](artifacts/implementation-decision-log.md#trivial-decisions)).
- The "closing a pr9k pane closes the run" disclosure added to the cmux footer pane's inline `?` help (`buildFooterHelpLines()`) and to `docs/how-to/setting-up-cmux.md` ([D-10](artifacts/implementation-decision-log.md#d-10-the-d7-help-disclosure-target-is-the-cmux-footer-panes-inline--help-not-the-uigo-helpmodal-constants)).
- An explicit `bufio` flush after the classified abort diagnostic is written, and an `os.Exit()`-free abort path so the deferred `log.Close()` flush always runs ([D-11](artifacts/implementation-decision-log.md#d-11-abort-diagnostic-durability-is-a-bufio-flush-before-subsequent-abort-steps-osexit-is-prohibited-on-the-abort-path)).

When operators run `pr9k --cmux --project-dir <repo>` against a real workflow and a failure occurs: a display-pane death, an operator pane-close, a channel stall, a cmux call timeout, or a mid-run cmux error all converge on one clean abort — the running step's subprocess is terminated, the classified diagnostic is written to the per-run log file, exactly one run-aborted notification fires, the sidebar entries clear, the panes render `run aborted` and exit promptly, and pr9k exits non-zero with the workspace left open for inspection. If the orchestrator process itself dies, each display pane detects the lost channel within 45 seconds (or promptly on a clean disconnect), renders `run aborted`, and exits, leaving an orphan workspace whose diagnostic lives in the launching terminal and the per-run log file.

## Context

- **Driving constraint:** Phases 1–5 built a working cmux core, but the multi-process architecture has more ways to fail than the single-process standard display, and Phase 5 [D15](../phase-5-lifecycle-notifications/artifacts/decision-log.md#d15-failure-modes-that-bypass-orchestrator-shutdown-are-phase-6-scope) explicitly delegated the non-graceful failure paths to Phase 6. Until Phase 6 ships, a display-pane death, a channel stall, or a hung cmux call leaves the operator in a confusing partial state — a frozen display, a stale sidebar, no signal the run ended. The value is in covering every failure mode together: leaving one out means an operator can still hit an uncovered partial state.
- **Stakeholders:**
  - **Operators running pr9k in cmux mode** — care that every failure mode produces a predictable, inspectable end state rather than a confusing partial one; that exactly one run-aborted notification fires per aborted run; that a long quiet step or a paused error-mode prompt never false-aborts; and that the workspace stays open so they can read what happened.
  - **pr9k maintainers** — care that the abort gate is provably one-way under `-race`; that the liveness/stall mechanism in `internal/interactionchannel` is testable without `time.Sleep`; that `ExitReasonAborted` keeps the infrastructure-abort path distinguishable from operator-quit; and that Phase 6 adds detection/convergence without re-architecting the synchronous `workflow.Run()` loop.
- **Future-state concern:** the liveness emitter and the per-connection stall timers are new always-on goroutines on every cmux run — they must drain cleanly on every exit path (`WaitGroup` join, context cancel) or they leak. The 45-second stall threshold and the 10-second liveness cadence are fixed exported constants; the spec reopen trigger ("operators report false-positive aborts in normal use, or that 45 seconds is too slow") is recorded for the next planner ([D-3](artifacts/implementation-decision-log.md#d-3-the-liveness-emitter-is-a-10-second-cadence-goroutine-started-after-awaitready-the-per-connection-stall-timer-lives-in-readloop)). Phase 7's orphan-workspace startup advisory consumes the orphan workspaces Phase 6 tolerates but does not clean up.
- **Out-of-scope boundary:** no display-pane respawn / stateful recovery (spec [D11](feature-specification.md#out-of-scope)); no confirmation prompt before the operator's pane-close gesture (cmux exposes no hook — spec Out of Scope); no automatic orphan-workspace cleanup (Phase 7 advisory reports them); no per-pane-role failure handling; no pre-run failure handling (Phase 1 lifecycle teardown — spec [D14](feature-specification.md#out-of-scope)); no rollback of target-repo side-effects of an aborted run (spec [D15](feature-specification.md#out-of-scope)); no operator-configurable thresholds, no per-failure-mode recovery flows, no per-failure-class exit-code taxonomy (all spec [Deferred (YAGNI)](feature-specification.md#deferred-yagni)); no live-cmux CI smoke test, no `fsync` on the abort log write, no structured/JSON abort records or metrics (this plan's [Deferred (YAGNI)](#deferred-yagni)).

## Implementation Approach

### Architecture and Integration Points

Phase 6 is detection-and-convergence work layered onto the already-shipped cmux orchestration. The discovery survey confirmed that the abort *sequence* itself already exists — `runCmuxWorkflowAdapted`'s user-quit path already runs `notifier.ExitErrorMode()` → `notifier.FireRunAborted(ctx)` → `sidebar.ClearAll(ctx)` on `ExitReasonUserQuit`. Phase 6's job is to make every failure-detection path converge on that sequence behind a single gate.

**New: the abort gate** ([D-1](artifacts/implementation-decision-log.md#d-1-the-abort-gate-is-a-synconce-guarded-one-way-transition-with-the-failure-cause-captured-in-the-do-closure)). A small `abortGate` struct in `src/cmd/pr9k/` wraps a `sync.Once`. `gate.trigger(cause AbortCause)` runs the `Do` closure that captures `cause` into a field and sets an `atomic` flag; every later `trigger` call is a no-op. `gate.IsAborting() bool` reads the atomic flag; `gate.Cause() AbortCause` reads the captured cause. The gate is constructed in `runCmuxOrchestratorWith` and shared with every detection path (the orchestrator's cmux-call wrapper, the per-connection `readLoop` stall/loss handlers). `AbortCause` is a typed value carrying the classified reason ([D-9](artifacts/implementation-decision-log.md#trivial-decisions)) for the diagnostic.

**New: the `runCompleted` flag** ([D-2](artifacts/implementation-decision-log.md#d-2-a-runcompleted-atomicbool-closes-the-post-run-window-race)). An `atomic.Bool` set at the instant `workflow.Run()` returns, before any terminal notification or `WorkspaceDone` broadcast. Every detection path checks `runCompleted.Load()` before calling `gate.trigger`; a post-run failure is dropped.

**Modification: `src/internal/interactionchannel/`** ([D-3](artifacts/implementation-decision-log.md#d-3-the-liveness-emitter-is-a-10-second-cadence-goroutine-started-after-awaitready-the-per-connection-stall-timer-lives-in-readloop), [D-5](artifacts/implementation-decision-log.md#d-5-panes-render-a-shared-run-aborted-token-aborted-bool-on-workspacedone-carries-the-clean-abort-path), [D-6](artifacts/implementation-decision-log.md#d-6-liveness-is-a-new-zero-field-message-type-with-wire-constant-liveness)). This is the largest new-work area — the package has no stall threshold and no heartbeat today.

- `messages.go` — add `Liveness{}` (zero fields), implementing the `Message` interface with `WireType()` returning the new wire constant `"liveness"`. Add an `Aborted bool` field to `WorkspaceDone` alongside the existing `ExitCode int`.
- `framing.go` — register the `"liveness"` case in `UnmarshalMessage`'s `"type"`-discriminator dispatch (additive; existing cases unchanged).
- `channel.go` — the per-connection `readLoop` gains a `time.Timer` created with an injected threshold (default `StallThreshold = 45 * time.Second`, exported) and an injected `onStall` callback; the timer is reset (Stop-drain-Reset) on every received message. On expiry, `onStall` fires. `ReadyHandshakeTimeout` and the existing clean-disconnect path are unchanged. A new exported `RunAbortedToken = "run aborted"` constant lives here (or in a shared cmux package — final placement is a one-line decision per [D-5](artifacts/implementation-decision-log.md#d-5-panes-render-a-shared-run-aborted-token-aborted-bool-on-workspacedone-carries-the-clean-abort-path)).
- `fake.go` — `FakeInteractionChannel` gains `HoldMessages()` / `ReleaseMessages()` so a test can wedge a channel deterministically to exercise the stall path (test-engineer F-D).

**Modification: `src/internal/workflow/`** ([D-4](artifacts/implementation-decision-log.md#d-4-an-abort-detected-on-a-channel-goroutine-interrupts-the-synchronous-run-loop-via-terminate--actionquit-routed-by-a-new-exitreasonaborted)). `exit_reason.go` gains `ExitReasonAborted`, a new typed-string-constant value alongside `ExitReasonCompleted` / `ExitReasonLoopBroken` / `ExitReasonUserQuit`. `run.go` returns it in `RunResult.ExitReason` when the loop exits because of an injected `ActionQuit` raised by the abort gate (distinguished from an operator-raised `ActionQuit` by the gate state). `Runner.Terminate()` is reused unchanged — it is exactly spec [D15](feature-specification.md#out-of-scope)'s existing subprocess-termination path.

**Modification: `src/cmd/pr9k/cmux_*.go`** — the orchestration wiring.

- `cmux_pane.go` — `runCmuxOrchestratorWith` constructs the `abortGate` and the `runCompleted` flag, starts the liveness emitter goroutine after `ch.AwaitReady` and before `runCmuxWorkflowAdapted` (on a `context.WithCancel`-derived context joined by a `WaitGroup`), and passes the gate into both the workflow adapter and the channel's connection setup. `runCmuxDisplayPaneWith` and `runCmuxFooterPaneWith` gain a `stalledCh` select arm: on stall or on `WorkspaceDone{Aborted: true}` they render a final line containing `RunAbortedToken` and **return** ([D-5](artifacts/implementation-decision-log.md#d-5-panes-render-a-shared-run-aborted-token-aborted-bool-on-workspacedone-carries-the-clean-abort-path)). The abort path returns through the `cobra` `RunE` error chain — no `os.Exit()` ([D-11](artifacts/implementation-decision-log.md#d-11-abort-diagnostic-durability-is-a-bufio-flush-before-subsequent-abort-steps-osexit-is-prohibited-on-the-abort-path)).
- `cmux_workflow.go` — `runCmuxWorkflowAdapted` branches on `ExitReasonAborted` (alongside the existing `UserQuit`/`Completed`/`LoopBroken` branches): write the classified diagnostic via `logger.Log()` then flush ([D-11](artifacts/implementation-decision-log.md#d-11-abort-diagnostic-durability-is-a-bufio-flush-before-subsequent-abort-steps-osexit-is-prohibited-on-the-abort-path)), `FireRunAborted`, `ClearAll`, broadcast `WorkspaceDone{ExitCode: 1, Aborted: true}`. The orchestrator's cmux-call wrapper checks `runCompleted` then calls `gate.trigger` on a steady-state cmux timeout or a mid-run cmux error ([D-9](artifacts/implementation-decision-log.md#trivial-decisions)). The per-connection stall/loss `onStall` callback does the same.
- `cmux_sidebar.go` — `ClearAll` is unchanged; the abort path and the existing `defer sidebar.ClearAll(...)` safety net can both run, so `ClearAll` stays idempotent ([D-8](artifacts/implementation-decision-log.md#trivial-decisions)).
- `cmux_footer_renderer.go` — `buildFooterHelpLines()` gains the "closing a pr9k pane closes the run" disclosure line ([D-10](artifacts/implementation-decision-log.md#d-10-the-d7-help-disclosure-target-is-the-cmux-footer-panes-inline--help-not-the-uigo-helpmodal-constants)). `cmux_footer_machine.go`'s select loop gains the `stalledCh` arm.

**No modification: `src/internal/cmuxctl/`** — the cmux RPC surface. The mid-run error classifier reuses `preflight.go`'s existing `classifyDialError` / `classifyIdentifyError` vocabulary ([D-9](artifacts/implementation-decision-log.md#trivial-decisions)); the in-flight-call wait (spec D10) is satisfied for free by `RealClient`'s serial queue ([D-7](artifacts/implementation-decision-log.md#trivial-decisions)). Abort-path calls pass `context.Background()` so they are not dropped by the queue's `ctx.Done()` escape.

### Data Model and Persistence

Phase 6 introduces no new persistent state, no schema change, and no on-disk artifact ([parent D17](../artifacts/decision-log.md#d17-log-file-artifacts-are-unchanged-in-cmux-mode)). The abort gate, the `runCompleted` flag, the liveness emitter, and the per-connection stall timers are all in-memory, per-run. The classified abort diagnostic is written into the existing per-run log file at `<projectDir>/.pr9k/logs/<stamp>/` — the single diagnostic sink ([D-11](artifacts/implementation-decision-log.md#d-11-abort-diagnostic-durability-is-a-bufio-flush-before-subsequent-abort-steps-osexit-is-prohibited-on-the-abort-path)); no structured/JSON abort record is added ([Deferred (YAGNI)](#deferred-yagni)).

### Runtime Behavior

**Launch and steady state.** `runCmuxOrchestratorWith` runs Phase 1 preflight, `RunPhase1` creates the workspace and panes, then `ch.AwaitReady` completes the readiness handshake. Immediately after `AwaitReady` and before `runCmuxWorkflowAdapted`, the liveness emitter goroutine starts ([D-3](artifacts/implementation-decision-log.md#d-3-the-liveness-emitter-is-a-10-second-cadence-goroutine-started-after-awaitready-the-per-connection-stall-timer-lives-in-readloop)) — broadcasting `Liveness{}` every 10 seconds in *every* workflow phase, including between steps and while a run is paused at a Phase 3 error-mode prompt. Each connection's `readLoop` runs a 45-second stall timer, reset on every received message; because the liveness emitter ticks at 10 seconds, an idle-but-healthy channel never trips the threshold.

**Abort detection and routing** ([D-1](artifacts/implementation-decision-log.md#d-1-the-abort-gate-is-a-synconce-guarded-one-way-transition-with-the-failure-cause-captured-in-the-do-closure), [D-2](artifacts/implementation-decision-log.md#d-2-a-runcompleted-atomicbool-closes-the-post-run-window-race), [D-4](artifacts/implementation-decision-log.md#d-4-an-abort-detected-on-a-channel-goroutine-interrupts-the-synchronous-run-loop-via-terminate--actionquit-routed-by-a-new-exitreasonaborted)). A failure is detected on one of four paths:

1. **Display-pane death** — the connection's `readLoop` sees EOF/broken-connection (clean disconnect, prompt) and removes the conn; the loss handler checks `runCompleted`, then calls `gate.trigger(causeDisplayLoss)`.
2. **Channel stall** — the connection's `readLoop` stall timer expires (45s of silence); `onStall` checks `runCompleted`, then calls `gate.trigger(causeChannelStall)`.
3. **cmux call timeout / mid-run cmux error** — the orchestrator's cmux-call wrapper observes a `*cmuxctl.TimeoutError`, a `*CmuxError`, or a `*PlaintextError`; it classifies the error ([D-9](artifacts/implementation-decision-log.md#trivial-decisions)), checks `runCompleted`, then calls `gate.trigger(cause)`.
4. **Operator pane-close** — indistinguishable from display-pane death (path 1).

The first `gate.trigger` to win runs the `Do` closure: it captures the cause, sets `IsAborting()`, calls `runner.Terminate()` (SIGTERM→3s→SIGKILL, unblocking the synchronous subprocess wait inside `Run()`), and sends `ActionQuit`. `workflow.Run()` returns `RunResult{ExitReason: ExitReasonAborted}`. Every later detection sees the gate already tripped and is absorbed.

**Abort sequence** (the clean-abort path, run by `runCmuxWorkflowAdapted` on `ExitReasonAborted`):

1. Write the classified diagnostic (`gate.Cause()`) via `logger.Log()`, then explicit `bufio` flush ([D-11](artifacts/implementation-decision-log.md#d-11-abort-diagnostic-durability-is-a-bufio-flush-before-subsequent-abort-steps-osexit-is-prohibited-on-the-abort-path)).
2. `notifier.FireRunAborted(ctx)` — fires exactly once (the gate guarantees one abort sequence). Abort-path call: every failure including timeout is non-fatal and logged ([D-8](artifacts/implementation-decision-log.md#trivial-decisions)).
3. `sidebar.ClearAll(ctx)` — clears the two sidebar entries; abort-path calls, non-fatal; a partial clear is an acceptable degraded state ([D-8](artifacts/implementation-decision-log.md#trivial-decisions)).
4. Broadcast `WorkspaceDone{ExitCode: 1, Aborted: true}` — panes render `run aborted` and exit promptly rather than waiting out the stall threshold ([D-5](artifacts/implementation-decision-log.md#d-5-panes-render-a-shared-run-aborted-token-aborted-bool-on-workspacedone-carries-the-clean-abort-path)).
5. Return through the `cobra` `RunE` chain with a non-zero code — no `os.Exit()`, so the deferred `log.Close()` flush runs ([D-11](artifacts/implementation-decision-log.md#d-11-abort-diagnostic-durability-is-a-bufio-flush-before-subsequent-abort-steps-osexit-is-prohibited-on-the-abort-path)). The workspace stays open ([parent D14](../artifacts/decision-log.md#d14-workspace-closure-is-operator-initiated)).

In-flight cmux calls at the moment of detection are handled for free: `RealClient`'s single-goroutine serial queue means the abort sequence's own calls (`FireRunAborted`, `ClearAll`) queue behind any call already in flight ([D-7](artifacts/implementation-decision-log.md#trivial-decisions)).

**Pane-side detection and rendering** ([D-5](artifacts/implementation-decision-log.md#d-5-panes-render-a-shared-run-aborted-token-aborted-bool-on-workspacedone-carries-the-clean-abort-path)). Each display pane and the footer pane select on `stalledCh` (fed by its own `readLoop` stall timer) and on `WorkspaceDone`:

- **Orchestrator-death / stalled-channel path** — `stalledCh` fires (or the `readLoop` sees a clean disconnect). The pane renders a final line containing `RunAbortedToken` on its own surface and returns. No coordination between panes — the operator sees the same token in each.
- **Clean-abort path** — `WorkspaceDone{Aborted: true}` arrives. The pane renders the same token and returns promptly.

**Post-run window** ([D-2](artifacts/implementation-decision-log.md#d-2-a-runcompleted-atomicbool-closes-the-post-run-window-race)). `runCompleted` is set the instant `Run()` returns. A pane death or stall observed after that is dropped by the `runCompleted` check — no spurious run-aborted notification fires on top of a completion. The stall-timer-vs-completion cosmetic race (a pane may render `run aborted` for a run that completed) is accepted per spec D13 — the completion notification fires before the outcome broadcast.

**Orchestrator death** ([D-5](artifacts/implementation-decision-log.md#d-5-panes-render-a-shared-run-aborted-token-aborted-bool-on-workspacedone-carries-the-clean-abort-path)). No in-process code runs — no gate, no `FireRunAborted`, no `ClearAll`, no broadcast. Each pane's `readLoop` detects the lost channel (clean disconnect promptly, or the 45s stall timer), renders `run aborted`, and returns. The workspace is an orphan with stale sidebar entries; the orchestrator's final error is in the launching terminal and the per-run log file (which may be truncated short of a force-kill, with no completion marker — [D-11](artifacts/implementation-decision-log.md#d-11-abort-diagnostic-durability-is-a-bufio-flush-before-subsequent-abort-steps-osexit-is-prohibited-on-the-abort-path)).

## Testing Strategy

Test surface follows Phase 5's precedent: extend the existing `FakeClient`, `FakeInteractionChannel`, and adapter-test patterns; no new test harness. Spec [OQ-2](feature-specification.md#open-items) is resolved here ([D-12](artifacts/implementation-decision-log.md#trivial-decisions)): **mocked unit/integration tests + a mandatory manual in-pane gate + a written manual test script; no live-cmux CI job** — cmux v0.64.7 has no headless mode and standard runners have no cmux server, so a live CI smoke test is not buildable.

- **Observable behaviors to test** (test-engineer T1–T16, prioritized): a held/wedged channel fires the stall path after the injected threshold (T1); the liveness signal keeps a quiet channel healthy (T2); a clean disconnect is detected promptly without the threshold (T13); concurrent abort triggers produce exactly one abort sequence and one `FireRunAborted` (the near-simultaneous multi-failure case); a post-run pane loss fires no run-aborted; each pane renders the exact token `run aborted` and returns on both the stall path and the `WorkspaceDone{Aborted:true}` path (T7, T14); `ExitReasonAborted` routes through `runCmuxWorkflowAdapted`'s abort branch; a mid-run `*CmuxError` classifies to the named cause and an unrecognized code preserves the raw code verbatim.
- **Test doubles posture:** `FakeInteractionChannel` gains `HoldMessages()`/`ReleaseMessages()` for deterministic stall simulation (test-engineer F-D); `FakeClient`'s existing `HangNext`/`HangRelease` exercise the cmux-timeout abort; the stall threshold and liveness cadence are injected so no test uses `time.Sleep` (`docs/coding-standards/testing.md`).
- **Edge cases requiring coverage:** the exactly-45-second inclusive boundary; a liveness tick arriving inside the stall window resets the timer; near-simultaneous pane-death + cmux-timeout; the post-run window; the stall-timer-vs-completion cosmetic race (accepted, asserted as non-fatal); a partial sidebar clear (one entry clears, one fails) continues shutdown.
- **Test levels:** unit (message round-trips, the stall timer, the abort gate, the `ExitReason` constant, pane render); integration (`runCmuxWorkflowAdapted` driven through the abort sequence with `FakeClient` + `FakeInteractionChannel`); the mandatory **manual in-pane gate** for any change touching `internal/cmuxctl` or `internal/interactionchannel`, exercising the manual test script's three scenarios — a deliberately quiet step that must *not* false-abort, a deliberate channel wedge that must abort within the stall window, and a near-simultaneous pane-death + cmux-timeout that must produce exactly one run-aborted notification.
- **Race detector:** `cd src && go test -race ./...` is the required gate; W3's abort-gate concurrency and W4's liveness/detection wiring are the primary `-race` targets.
- **Skipped / YAGNI tests** (test-engineer S1–S5): no live-cmux CI test (see [Deferred (YAGNI)](#deferred-yagni)); no test for a per-failure-class exit code (spec-deferred taxonomy); no test for hypothetical adversaries (no new trust boundary).

## Security Posture

No new attack surface. The new `Liveness{}` message and the `Aborted bool` on `WorkspaceDone` flow over the same Unix socket, with the same UID/process-tree trust model and the same filesystem-permission-based access control as every existing `interactionchannel` message. ## Deferred (YAGNI)

### Live-cmux macOS-runner CI smoke test

- **Why deferred:** evidence test failed. No CI infrastructure exists for it — cmux v0.64.7 has no headless mode and standard GitHub Actions macOS runners have no cmux server, so a live CI smoke test cannot be built. CI/observability for a capability the project cannot exercise. The mandatory manual in-pane gate plus the written manual test script cover the timing-sensitive paths instead ([D-12](artifacts/implementation-decision-log.md#trivial-decisions)).
- **Reopen when:** cmux publishes a headless test mode, or ships a Docker image a CI runner can run a real cmux server from.
- **Source:** R1 — `test-engineer` F-005, `devops-engineer` F-005.

### Explicit `fsync`/`sync()` syscall on the abort-path log write

- **Why deferred:** simpler-version test. An `fsync` is speculative hardening against immediate OS page-cache loss with no demonstrated incidence. A `bufio.Flush()` (or a `log.Writer()` direct write) before the subsequent abort steps satisfies the same evidence — diagnostic durability on the orchestrator-survivable path — so the simpler version is recorded as the decision ([D-11](artifacts/implementation-decision-log.md#d-11-abort-diagnostic-durability-is-a-bufio-flush-before-subsequent-abort-steps-osexit-is-prohibited-on-the-abort-path)).
- **Reopen when:** a maintainer debugging a real abort reports the `bufio`-flushed diagnostic was still lost (host-level page-cache loss on a crash).
- **Source:** R1 — `devops-engineer` F-001.

### Structured/JSON abort-event records, metrics, dashboards, an orphan-workspace registry

- **Why deferred:** evidence test failed. Speculative observability — pr9k is a local developer CLI with no telemetry pipeline. The classified diagnostic in the per-run log file is the single sink ([D-11](artifacts/implementation-decision-log.md#d-11-abort-diagnostic-durability-is-a-bufio-flush-before-subsequent-abort-steps-osexit-is-prohibited-on-the-abort-path)).
- **Reopen when:** a maintainer debugging a real abort reports the classified diagnostic plus the abort-path-failure log lines are insufficient to diagnose what happened.
- **Source:** R1 — `devops-engineer` F-003, F-004.

> **Note — test injectability is not a deferred production knob.** The stall threshold and liveness cadence are *injectable in tests* (test-engineer F-A) so unit tests run without `time.Sleep`. This is **not** an operator-facing configuration knob: production always uses the fixed exported constants `StallThreshold = 45 * time.Second` and `LivenessCadence = 10 * time.Second`. The spec already deferred *operator-configurable* thresholds at the spec level (spec [Deferred (YAGNI)](feature-specification.md#deferred-yagni)); test injection and that deferred knob are different things and the plan does not conflate them.
