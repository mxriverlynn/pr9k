# Discovery Notes: Phase 6 — Robust Failure Handling

Static project context gathered before launching the specialist team. Specialists must read this first and not re-grep for what is already here. Search further only for what your domain specifically needs that this document does not cover.

## Tech Stack (project-discovery)

- **Language:** Go 1.26.2.
- **Test:** `cd src && go test -race ./...` or `make test`. Race detector is required by the testing standard.
- **Build:** `make build` (writes to `bin/`). `go build` is required — `go run` does not work because `workflowDir` resolves via `os.Executable()`.
- **Lint / vet / CI:** `make lint`, `make vet`, `make ci`.
- **TUI / process model:** Bubble Tea + Lip Gloss (standard mode). Cmux mode is multi-process under **Architecture A** (parent D-R1): the orchestrator is the in-pane pr9k process the operator launched — there is no hidden orchestrator pane. The only cmux-spawned processes are the three display panes (header / log / footer), coordinated by the `internal/interactionchannel` Unix-socket IPC.
- **cmux pin:** v0.64.7 (commit `2f96c15c2`); the cmux v2 `{ok,result,error}` envelope plus the bare plaintext `ERROR:` line are the contract of record (parent D-R2).

## Touch Points (code the implementation will extend)

> **Key discovery:** Phases 1–5 have already shipped, and the codebase is further along than a Phase-6-only reading of the spec would suggest. Several mechanics the spec treats as "reuse existing path" already exist as named functions. Phase 6 is predominantly **detection + convergence** work, not new-surface work.

### `src/internal/interactionchannel/` — Unix-socket IPC (the largest new-work area)

- `channel.go` — `Channel`: `Serve`, `Dial`, `Send`, `Recv() <-chan Message`, `SendStateHeader/Log/Footer`, `AwaitReady`, `Close`. `ReadyHandshakeTimeout = 10 * time.Second` (`channel.go:18`).
- Per-connection goroutine model: each accepted connection runs a **read loop**, a **write loop**, and a **watcher** goroutine. `writeLoop` services outbound sources via `select`.
- **Loss detection today: clean disconnect / EOF only.** When `io.ReadFull` errors, `readLoop` returns and the conn is removed via `removeConn`. **There is NO stall threshold, NO heartbeat, NO liveness mechanism of any kind.** D2's 45-second stall threshold and D3's content-independent liveness signal are entirely new work for this package — the single biggest implementation item in Phase 6.
- `framing.go` — `uint32` big-endian length-prefix + JSON; `"type"` discriminator injected at serialize time; 1 MiB max frame; `UnmarshalMessage` dispatches on `"type"`.
- `messages.go` — `Message` interface (`WireType() string` + `sealed()`). Pane→orch: `Ready{Role}`, `Intent{Kind}`, `DoneAck{Role}`. Orch→pane: `StateHeader`, `StateLog`, `StateFooter`, `WorkspaceDone{ExitCode int}`. A new liveness message type and possibly a new abort-outcome shape (or reuse of `WorkspaceDone`) are Phase 6 decisions.
- `fake.go` — `FakeInteractionChannel`, `FakeDisplayPane` (dials a real socket; supports `SetSlowConsumer` / `SetPrematureExit` — directly useful for stall/loss tests), `FakeFooterKeySource`.
- Tests: `channel_test.go`, `fanout_test.go`, `framing_test.go`, `awaitready_test.go`, `fake_test.go`. `/tmp`-based socket paths avoid the macOS `sun_path` length limit. `t.Parallel()` is used.

### `src/internal/cmuxctl/` — cmux v2 RPC surface

- `client.go` — `CmuxClient` interface; `WorkspaceNotify` (→ `notification.create_for_target`), `WorkspaceClearStatus` (→ `workspace.clear_status`), `WorkspaceClearProgress` (→ `workspace.clear_progress`), plus the `NotificationClass` typed constants all already exist (Phase 5 work).
- `real.go` — `RealClient` single-goroutine sequential queue; all cmux calls are serialized, never interleaved. `DefaultTimeout = 8 * time.Second`. On timeout the socket is closed (`disconnect()`); the next call re-dials.
- `errors.go` — **a typed `TimeoutError{Method, Duration}` already exists** (Phase 5 introduced it). Callers detect timeouts with `errors.As(err, &TimeoutError{})`. `*CmuxError{Code, Message}` is the structured envelope; `*PlaintextError{Raw}` is the bare `ERROR:` line with `.IsAccessDenied()`.
- `preflight.go` — `Preflight` runs 5 sequential checks; `classifyDialError` and `classifyIdentifyError` **already classify** access-denied, `auth_required`/`auth_failed`/`auth_unconfigured`, and `method_not_found`/`unknown_method`. **D5's mid-run classification can reuse this existing vocabulary** — the work is routing a mid-run error through a classifier, not inventing one.
- `fake.go` — `FakeClient`: per-method `*Func` scriptable fields + recorder slices; `HangNext`/`HangRelease` channels simulate a hanging RPC (directly useful for the cmux-timeout abort tests). All state `mu`-guarded; `NotifyCallsSnapshot()` is race-safe.
- Tests: `cmuxctl_test.go`, `preflight_test.go`, `hangrace_test.go` (race-detector stress), `notify_test.go`, `dismissal_test.go`, `runphase1_test.go`.

### `src/cmd/pr9k/cmux_*.go` — cmux orchestration (Phases 1–5)

- `cmux_notifier.go` — `cmuxNotifier` with **`FireRunAborted(ctx)`** (fires `notification.create_for_target`, body `"pr9k run aborted in <repo>"`), `FireCompletion(ctx)`, `EnterErrorMode`/`ExitErrorMode`. Phase 6 reuses `FireRunAborted` as-is; D9's "exactly once" is a guard *around* this call, not a change to it.
- `cmux_workflow.go` — `runCmuxWorkflowAdapted` wires the channel adapters and calls `workflow.Run(...)`. **The existing user-quit abort path already does:** `notifier.ExitErrorMode()` → `notifier.FireRunAborted(ctx)` → `sidebar.ClearAll(ctx)`, on `ExitReasonUserQuit`, returning exit code `1`. **This is the exact sequence D1 generalizes to every survivable failure.** Phase 6's job is to make every failure-detection path converge on this sequence behind the single abort guard.
- `cmux_pane.go` — `runCmuxOrchestratorWith`: `AwaitReady` → run workflow → `ch.Send(WorkspaceDone{ExitCode})` → `awaitDoneAcks(ch.Recv(), ackTimeout)` (`workspaceDoneAckTimeout = 5s`). **The `WorkspaceDone` broadcast already exists** — D13's "broadcast the aborted outcome" routes the abort path through this same broadcast. Also defines `runCmuxDisplayPaneWith` / `runCmuxFooterPaneWith` (the display-pane entry points that must learn to detect a lost channel and render "run aborted").
- `cmux_sidebar.go` — `cmuxSidebar`, `ClearAll` (calls `WorkspaceClearStatus` + `WorkspaceClearProgress`); each clear logs-and-continues on error. D6's abort-path-non-fatal rule matches this existing shape.
- `cmuxctl/runphase1.go` — `RunPhase1` owns the workspace lifecycle, the `DismissalObserver`, and the post-teardown `WorkspaceClose`. D14 confirms `WorkspaceClose` is teardown-only, not part of the abort sequence.

### `src/internal/workflow/` — the Run loop and subprocess termination

- `run.go` — `Run()` drives initialize → iteration loop → finalize **on a single goroutine**; all subprocess I/O is synchronous inside `Runner` methods called from `ui.Orchestrate`. `RunResult.ExitReason` ∈ {`ExitReasonCompleted`, `ExitReasonLoopBroken`, `ExitReasonUserQuit`}. **Phase 6 likely adds a new `ExitReason` (or equivalent) for an infrastructure abort** so `runCmuxWorkflowAdapted` can route to the abort sequence — this is an open implementation question.
- `workflow.go` — `Runner.Terminate()`: `SIGTERM` to the process group → 3s grace → `SIGKILL`; the per-step timeout path is similar with a 10s grace. A `WARN-002` flag-claiming protocol ensures only one of `terminated`/`timeoutFired` wins. **D15's "terminate the running step's subprocess through the existing path" is exactly `Runner.Terminate()`.**

### `src/internal/logger/` — per-run log file

- `logger.go` — log file at `<projectDir>/.pr9k/logs/<prefix>-YYYY-MM-DD-HHMMSS.mmm.log`; `bufio.Writer`-buffered. **The `bufio` buffering is relevant to D12:** a force-kill can lose un-flushed buffered content, which is one source of the truncation D12 documents. `RunStamp()` names the per-run artifact dir.

### Help modal + how-to (D7 disclosure targets)

- `src/internal/ui/ui.go:48–70` — `HelpModal*` constants (`HelpModalNormal`, `HelpModalSelect`, `HelpModalError`, `HelpModalDone`). **None mention pane-close.** `renderHelpModal()` is in `src/internal/ui/model.go:595`. **Caveat:** the cmux footer pane does NOT use `renderHelpModal` — it has its own inline `?` help via `cmux_footer_machine.go`. Phase 6 must add the "closing a pr9k pane closes the run" disclosure to whichever help surface the operator actually sees in cmux mode (the footer pane's help), and confirm which that is.
- `docs/how-to/setting-up-cmux.md` — the cmux setup how-to; no current mention of pane-close aborting a run. The disclosure belongs near the pane-navigation / dismissal sections.

## Gaps and open questions surfaced during discovery

Surfaced for the team to settle — not pre-decided here.

1. **Liveness signal: message type, cadence, and emitter goroutine.** D3 fixes the *behavior* (orchestrator emits, content-independent, every phase, sub-threshold cadence) but leaves the mechanism implementation-owned. The team must pin: a new `Message` type vs. reuse; the cadence value (well below 45s — e.g. 5–15s); where the emitter goroutine lives and how it is started before the stall timer counts (D3 requires this ordering); how it is stopped on the abort path.
2. **Stall-timer placement, symmetric on both sides.** D2 says the 45s threshold applies symmetrically — orchestrator detecting a pane, and a pane detecting the orchestrator. The orchestrator runs the workflow on a single goroutine; the display panes have their own read loops. The team must pin where each side's stall timer lives and how it resets on every received message (D3: "any message within the threshold window" keeps the channel healthy).
3. **The single one-way abort transition.** D1 requires one shared abort gate checked by every detection path (cmux-call timeout, channel stall, display loss, mid-run cmux error). The team must pin the concrete primitive (a `sync.Once`-guarded state flag, an atomic CAS, a channel close) and ensure every detection path — some on the orchestrator's single goroutine, some on channel goroutines — checks it race-free under `-race`.
4. **New `ExitReason` / abort routing.** Today `runCmuxWorkflowAdapted` branches on `RunResult.ExitReason`. An infrastructure abort (display loss, stall, cmux timeout) is not a `workflow.RunResult` outcome — the workflow `Run()` loop is purely synchronous and unaware of the channel. The team must pin how an abort detected on a channel goroutine interrupts the synchronous `Run()` loop and routes to the `FireRunAborted` → `ClearAll` sequence (e.g., terminate the running step's subprocess to unblock `Run()`, then a sentinel checked after `Run()` returns).
5. **In-flight cmux call wait (D10).** `RealClient` serializes calls and bounds each by `DefaultTimeout`. The team must pin how the abort path observes "is a call in flight, and has it finished" — the serial queue may make this naturally satisfied (the abort sequence's own calls simply queue behind the in-flight one), which would make D10 nearly free. Confirm.
6. **Pane-side "run aborted" rendering.** D4 requires each display pane to render a final line containing the token "run aborted" on lost-channel detection. The header/log/footer panes render differently; the team must pin how each pane composes that line within its existing render path, and that the token is exactly `run aborted` for testability (spec User Interactions F16).
7. **OQ-2 / live-cmux CI smoke test (spec Open Items).** The spec records a test-strategy question: continue mocked tests + a mandatory manual in-pane gate, vs. also adding a live macOS-runner CI smoke test for the timing-sensitive failure modes. The spec recommends mocked + manual gate + a manual test script; whether to add live CI is explicitly a team decision for implementation planning. `test-engineer` and `devops-engineer` must settle this.
8. **`feature-technical-notes.md` does not exist for Phase 6** — the spec captured no load-bearing mechanics file (Summary: "Technical notes captured: none"). There is no `T#` set; the `T#-contradiction` classification does not apply.
