## Coding standards (path + relevance)

- `docs/coding-standards/file-writes.md` — Rule 1: `atomicwrite.Write` for replacement; Rule 3: no `O_TRUNC` in new code; iteration log's `O_APPEND` is the documented pattern. **State-file writer must use `atomicwrite.Write`.**
- `docs/coding-standards/concurrency.md` — snapshot-then-unlock, mutex-protected writes, non-blocking channel sends. State-file write happens once on the main goroutine before subsystem construction; no new shared state needed.
- `docs/coding-standards/error-handling.md` — package-prefixed messages (`workflow:`, `preflight:`), file paths in I/O errors, scanner error checking.
- `docs/coding-standards/go-patterns.md` — `EvalSymlinks` is required for both `--workflow-dir` and `--project-dir`. **Path-comparison rule** (resume validation) must follow this standard — confirmed in T4 of the spec.
- `docs/coding-standards/testing.md` — race detector mandatory; closeable idempotency tests; test-helper path resolution.
- `docs/coding-standards/api-design.md` — bounds guards, precondition validation, adapter types. `RunResult` adding an `ExitReason` enum field is consistent.
- `docs/coding-standards/lint-and-tooling.md` — **lint suppressions are prohibited**. No `//nolint` allowed; any new lint failure must be fixed at the root.
- `docs/coding-standards/tui-rendering.md` — plain-text-first ANSI composition; `lipgloss.Width()`; `render_*.go` per component.
- `docs/coding-standards/versioning.md` — pr9k's public API includes CLI flags, `config.json` schema, `{{VAR}}` language. Adding `worktrees` block, `--fresh`, and `pr9k worktree prune` is a minor-version surface bump under 0.y.z rules.
- `docs/coding-standards/documentation.md` — feature docs ship with the feature; CLAUDE.md must be updated when a new doc file is added.

## Code touch points

### Entry point and CLI
- `src/cmd/pr9k/main.go` — `main()` currently calls `cli.Execute()`, then `startup()`, then `workflow.Run()` and discards the result (`_ = workflow.Run(...)`). The state-file lifecycle (read at startup, write after `preflight.Run` on fresh paths, remove on `Completed`/`LoopBroken`) inserts here.
- `src/internal/cli/args.go` — `Config{Iterations, WorkflowDir, ProjectDir}` and `NewCommand(cfg)`. The `--fresh` flag is added to the root command. The workflow-builder TUI and sandbox subcommands have their own commands and ignore the worktrees block (D9).
- Subcommands live in `src/cmd/pr9k/`: `sandbox.go`, `sandbox_create.go`, `sandbox_interactive.go`, `sandbox_shell.go`, `workflow.go`. A new `worktree.go` (with subcommands `prune`, `prune --dry-run`) is the natural site for D14.

### Project / workflow dir resolution
- `src/internal/cli/args.go:resolveWorkflowDir` — two-candidate resolution against `cfg.ProjectDir`. **Must run against the primary, not the worktree** (T1).
- `src/internal/cli/args.go:resolveProjectDir` — uses `os.Getwd()` + `EvalSymlinks`.

### Startup pipeline
- `src/cmd/pr9k/main.go:startup` — loads `StepFile`, runs validator, runs `preflight.Run(projectDir, ...)`, opens logger, creates per-run artifact dir at `<projectDir>/.pr9k/logs/<runStamp>`, returns a `*workflow.Runner` constructed with `projectDir`. **Project-dir is the worktree on enabled-true paths.**
- `src/internal/preflight/run.go:Run` — currently calls `os.MkdirAll(projectDir/.pr9k, 0o755)`. Under T1's redirect this creates `<worktree>/.pr9k/`, not `<primary>/.pr9k/`. The state-file writer therefore needs its own `os.MkdirAll(<primary>/.pr9k, ...)` before calling `atomicwrite.Write` (T4 §Lifecycle).

### Workflow runner
- `src/internal/workflow/workflow.go:NewRunner(log, projectDir)` — constructs the Runner; `projectDir` is captured here. Container bind-mount source is `r.projectDir` in `RunSandboxedStep` / `BuildRunArgs` callsite.
- `src/internal/workflow/workflow.go:RunSandboxedStep` and `runCommand` set subprocess `cmd.Dir`; the worktree path flows here.
- `src/internal/workflow/run.go:Run` — orchestrates phases. Returns `RunResult{IterationsRun int}`. **Adding `ExitReason` is the D16 change.** Three return sites currently use `RunResult{}` / `RunResult{IterationsRun: ...}`:
  - early-return on user quit during initialize phase (`run.go:460`)
  - early-return on user quit during iteration phase (`run.go:589`)
  - early-return on user quit during finalize phase (`run.go:722`)
  - normal completion (`run.go:749`)
  - **`breakLoopIfEmpty` exit** (`run.go` near 615) currently falls through to natural completion — must be distinguished from `Completed` for D16.
- `src/internal/workflow/iterationlog.go` — `IterationRecord` schema (`SchemaVersion 1`); `AppendIterationRecord(projectDir, rec)` opens `<projectDir>/.pr9k/iteration.jsonl` with `O_WRONLY|O_CREATE|O_APPEND, 0o644`. **Adding the `invocation_stamp` field is the D17/T5 change.** Field must be set at the single record-construction layer (`newIterationRecord` and the timeout-record / prep-record sites near `run.go:417, 437, 656, 698`). `SchemaVersion` is currently a load-bearing field on every record — adding a new field is non-breaking by JSON omitempty rules but the consumers (`post_issue_summary` jq filter, `lessons-learned` corpus read) tolerate unknown fields.
- `IterationRecord.SchemaVersion` is unrelated to the active-run state file's `schemaVersion`; both names coexist.

### Sandbox bind-mount layout
- `src/internal/sandbox/command.go:BuildRunArgs` — bind-mounts `projectDir` → `/home/agent/workspace`. Sibling-of-primary worktree path lives under `$HOME` on macOS, default-shared in Docker Desktop (D1 evidence).
- `src/internal/sandbox/image.go` — `ContainerRepoPath = "/home/agent/workspace"`.

### Atomic write primitive
- `src/internal/atomicwrite/write.go:Write(path, data, mode)` — temp-file + rename + parent-dir fsync; symlink-preservation; ENOENT first-save walk; EXDEV propagation. **Used directly by `workflowio.Save`; reuse for the state file.**

### Crash-temp / PID-liveness pattern (precedent for state-file PID check)
- `src/internal/workflowio/crashtemp.go:classifyPID(pid int)` — wraps `syscall.Kill(pid, 0)`. The state-file's PID liveness check follows this pattern (T4). Binary-path comparison is new: `proc_pidpath`/`/proc/<pid>/exe`/`ps` fallback per OS — not yet present in the codebase.

### Workflow config / validator
- `src/internal/workflowmodel/scaffold.go:rawConfig` — JSON schema parse target. **Adding `worktrees` block requires updating `rawConfig` AND `WorkflowDoc` AND the validator's `vFile`.**
- `src/internal/validator/validator.go:vFile` — uses `DisallowUnknownFields`. **Adding `worktrees` here is mandatory or `config.json` parsing rejects the new block.**
- `src/internal/validator/validator.go:ValidateDoc` — current categories include parse, file existence, scope resolution, env passthrough, containerEnv, captureMode, effort and defaults, sandbox isolation rules B and C, statusLine. **Adding a `worktrees` category that rejects `autoCleanup: true` without `enabled: true` is a small addition; pattern matches existing `vDefaults`.**
- `src/internal/workflowio/marshal.go` — outbound JSON shape (workflow-builder TUI saves). **Must round-trip the `worktrees` block** so users editing via `pr9k workflow` don't lose their worktree config.

### Default workflow scripts
- `workflow/scripts/git_push` — currently `trap 'exit 0' EXIT; result=$(git push); echo $result; exit 0`. **D7's three-part change lands here: surface non-zero exits, set upstream on first push, drop the trap.** Applies to BOTH worktree and in-place modes (resolved OI-1).
- `workflow/scripts/review_verdict` — currently reads `code-review.md` from CWD. **OI-2 fix: `REVIEW_FILE=".pr9k/artifacts/code-review.md"`.**
- `workflow/scripts/post_issue_summary` — reads `.pr9k/iteration.jsonl` with `jq` (no `issue_id` filter). The cross-issue contamination on resumed runs is an accepted limitation per D17.
- `workflow/prompts/lessons-learned.md` — references `.pr9k/iteration.jsonl` literally; truncates it at end. **Path is unchanged under T5; consumer continues to work without modification.**
- `workflow/config.json` — the iteration phase ordering currently runs `Close issue` (line 28-ish) before `Git push` (line 29-ish). **D18 reorder: swap.** D7 also requires this swap so a kill window doesn't leave issue closed without commits pushed.

### Logger
- `src/internal/logger/` — produces millisecond-precision wall-clock stamps; `RunStamp()` returns it. **Reused as the source for both worktree-stamp and invocation-stamp.** Two stamps are conceptually distinct moments (worktree creation vs invocation start).

### Final summary
- `src/internal/ui/log.go:CompletionSummary(iterationsRun, finalizeCount)` — current signature has no slot for worktree path / branch / count. **D11/JD-003 commit to extending this; the implementation can extend the existing function or compose a second line.**
- `src/internal/ui/header.go:IterationLine` — free-text field on `StatusHeader`. The basename prefix (and "(resumed)" suffix) lands here without new TUI infrastructure (D11/JD-002).

## Explicitly enumerated gaps

These items were searched for and **not found**; their absence is itself a finding:

1. **No precedent for a separate state file at `<primary>/.pr9k/active-run.json`.** The existing `.pr9k/` umbrella holds `iteration.jsonl`, `logs/`, `artifacts/`, but no JSON state file. The state-file writer creates `.pr9k/` (T4 lifecycle).
2. **No precedent for binary-path identity check.** `crashtemp.classifyPID` does PID-only liveness. The new identity check (`/proc/<pid>/exe` on Linux, `proc_pidpath` on macOS, `ps`-based fallback) has no existing helper. The implementation introduces this primitive.
3. **No precedent for per-process git-worktree management.** The codebase shells out to `git` via `Runner.RunStep`, but no module currently invokes `git worktree add/list/remove`. The implementation adds a new package or in-line helper for the worktree lifecycle (creation, removal, discovery, branch deletion).
4. **No `docs/how-to/` entry yet** for the worktrees feature, the prune subcommand, or `--fresh`. The documentation standard (`docs/coding-standards/documentation.md`) requires shipping these alongside the feature.
5. **No existing tests covering `RunResult` consumers.** Today `main.go` discards the value (`_ = workflow.Run(...)`); the implementation must add tests for the four/five `ExitReason` paths and for the cleanup branching that depends on it.
6. **No existing schema-version migration framework.** The active-run state file's `schemaVersion: 1` is committed; the spec defers migration tooling. The implementation must reject unknown versions cleanly (rename with `.incompatible-<timestamp>` suffix) without introducing a migration framework.
7. **No existing `pr9k worktree` subcommand group.** `sandbox` is the only multi-subcommand group; the new `worktree` group adds at least `prune` and `prune --dry-run`.
8. **No CLAUDE.md update for the new feature documentation files.** The standard requires it; the implementation plan must include this as work.
9. **Push step has not been edited in 90 days; D7's failure-mode-routing change is genuinely the first change in a long time** — consumers may be implicitly depending on the trap. The implementation must verify nothing else relies on `git_push` always exiting zero.
10. **The validator currently rejects unknown top-level keys (`DisallowUnknownFields`).** Without a coordinated change to `validator.go`, `workflowmodel/scaffold.go`, and `workflowio/marshal.go`, adding `worktrees` to a real `config.json` will fail the validator. This is a coordinated three-file change.
